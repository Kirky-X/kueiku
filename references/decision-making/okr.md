# OKR · Objectives & Key Results

## Core Concept

Created by Andy Grove at Intel, popularized by John Doerr at Google. Through **clear Objectives (O)** and **quantifiable Key Results (KR)**, transform organizational intent into executable, measurable actions.

```
Objective: Inspiring qualitative direction description
  ↓
Key Result 1: Quantified milestone, verifying objective progress
Key Result 2: Quantified milestone
Key Result 3: Quantified milestone
  ↓
Initiatives: Specific action plans to achieve KRs
```

**Core distinction:**
- **Objective** = What (where to go) — qualitative, inspiring, with time boundary
- **Key Result** = How we know we're getting there — quantitative, verifiable
- **Initiative** = How (how to do it) — specific tasks, not part of KR

---

## Applicable Scenarios

✅ **Best suited for**
- Quarterly/annual goal setting and organization-wide alignment
- Building team priority consensus
- Personal/team growth goal setting
- Layer-by-layer decomposition from strategy to execution

⚠️ **Use with caution**
- For performance evaluation (linking OKR to performance causes KR to become conservative)
- Daily operational work (SLA/KPI suffices; OKR is for challenging goals)
- Tasks shorter than 1 month (Eisenhower Matrix more appropriate)

---

## Objective Writing Standards

**Good O:**
✅ Qualitative, describing desired state
✅ Inspiring, making team feel worth striving for
✅ Has time boundary (this quarter)
✅ Action-oriented (starts with verb)

**Bad O:**
❌ Contains numbers (that's KR's job)
❌ Dull description ("Complete product iteration")
❌ Too grand to make progress in one quarter

```
❌ "Improve product quality" — Too vague
❌ "DAU grows 20%" — This is KR, not O
✅ "Become the indispensable work partner users rely on daily" — Directional, inspiring
✅ "Establish leading brand awareness in East China market" — Clear, bounded
```

---

## Key Result Writing Standards

**Good KR:**
✅ Quantifiable (has specific numbers)
✅ Has deadline
✅ Result-oriented, not task-oriented
✅ Ambitious but achievable (60-70% achievement rate is healthy signal)
✅ Truly measures Objective progress

**Bad KR:**
❌ Task-based ("Complete XX feature development") — This is Initiative
❌ Cannot quantify ("Improve user satisfaction")
❌ Too conservative (Ensuring 100% achievement leads to unchallenging goals)

```
❌ "Complete new homepage redesign" — This is Initiative, not result
❌ "Improve user experience" — Cannot quantify
✅ "Increase D7 retention rate from 28% to 38% by end of Q2" — Clear result + numbers + time
✅ "Increase average monthly Core Feature usage from 3 times to 8 times" — Quantifies behavior change
```

## OKR Hierarchy Design

### Company-level OKR

Directional, cross-quarter or even annual large goals, typically 3-5 Os.

### Team-level OKR

Sub-goals supporting company OKR. Each team OKR should clearly answer: "How does this advance company OKR achievement?"

### Personal OKR (Optional)

For personal growth and contribution alignment with team OKR.

**Cascade principle**: Not simply decomposing and distributing company OKR, but each team level **proactively sets** how to support superior OKR based on their own responsibilities.

## Execution Steps

### Step 1: Gather Input

- Previous cycle review: Which KRs completed? Which didn't? Why?
- Strategic direction: What are company's most important current challenges/opportunities?
- External input: SWOT analysis, PESTLE, user feedback

### Step 2: Draft Objectives

Team brainstorm, draft 3-5 Objectives.
Test with: "If we achieved this O, where would company/team be? Is this inspiring?"

### Step 3: Develop Key Results for Each O

Each O corresponds to 2-5 KRs, ensuring KRs truly measure O achievement, not just activity lists.

**KR diversity check**: Do all KRs of one O cover different angles? (e.g., efficiency metrics + quality metrics + user metrics)

### Step 4: Establish Scoring Consensus

Reach consensus: KR target values set at **70% confidence achievement** level (stretch goal).
Define in advance: What counts as 1.0 (fully achieved) / 0.7 (mostly achieved) / 0.3 (partially achieved).

### Step 5: Check Alignment and Dependencies

- Are team OKRs aligned with company OKR?
- Are there cross-team dependencies needing advance negotiation?

### Step 6: Periodic Check-ins

- **Weekly**: 1-2 sentence KR progress update, any blockers?
- **Monthly**: Score each KR (0.0-1.0), adjust Initiatives
- **Quarter-end**: Full scoring + learning summary + next quarter OKR development

Team: [...]

Objective 1: [Inspiring qualitative goal]

  KR 1.1: [Metric] increase from [current value] to [target value], deadline [date]
  KR 1.2: [Metric] increase from [current value] to [target value], deadline [date]
  KR 1.3: [Metric] increase from [current value] to [target value], deadline [date]

  ...

## Common Pitfalls

| Pitfall | How to Avoid |
|------|---------|
| KR written as To-Do list | Distinguish Initiative (task) and Key Result (result)|
| Too many objectives | Max 3 Os per team, max 4 KRs per O |
| OKR linked to performance evaluation | Separate OKR (growth/challenge) from performance evaluation system |
| Only paying attention late in quarter | Bi-weekly/monthly mandatory check-ins |
| All KRs 1.0 completed | Indicates goals too conservative, need to increase challenge level |

## Relationship with Other Methodologies

- **Precedes SWOT**: SWOT identifies strategic opportunities and threats, converts to OKR Objectives
- **Combined with RICE**: OKR defines KRs to achieve, RICE prioritizes implementation paths (features/projects)
- **Combined with Eisenhower Matrix**: OKR Objectives define what is "important," matrix helps identify Q2 tasks
- **Combined with Lean BML**: OKR KRs are success metrics, BML loop validates implementation path effectiveness
