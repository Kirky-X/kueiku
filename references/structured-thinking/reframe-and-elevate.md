# Reframe and Elevate

## Core Concept
When stuck on a problem, reframe it (change the question) or elevate it (move to a higher abstraction level). Often, being stuck means you're solving the wrong problem or at the wrong level.

## Applicable Scenarios
✅ **Best for**
- Problem stuck situations
- Innovation breakthroughs
- Strategic repositioning
- Dilemma decisions

⚠️ **When NOT to use**
- The problem statement is fine and the real blocker is execution — reframing becomes productive procrastination; attack the blocker instead
- Live incidents and time-boxed operations — "what if the constraint didn't exist?" is a planning-room move; in crisis, work the constraint (**OODA Loop**)
- The current frame was deliberately negotiated with stakeholders — re-opening the question undoes an agreement without adding information; escalate through the agreed process
- As a serial escape — one more reframe always feels possible; cap candidates at 2-3 and then choose, or nothing lands

## Key Steps
1. State the current problem frame clearly
2. Ask: "Am I solving the right problem?"
3. Reframe: restate the problem from a different perspective
   - "How would a competitor see this?"
   - "What if the constraint didn't exist?"
   - "What's the opposite of my current assumption?"
4. Elevate: move to a higher abstraction level
   - "What's the broader system this problem is part of?"
   - "What goal does this problem serve?"
5. Select the most productive new frame; proceed with the new framing

## Output Template

```
Current frame: [the question as currently stated] — stuck because [why]
Reframe candidates:
  - Other actor's view: "How would [competitor / customer / regulator] state this?" → [restated question]
  - Constraint removal: "What if [constraint] didn't exist?" → [restated question]
  - Assumption inversion: "What if [core assumption] were false?" → [restated question]
Elevation: this problem serves [higher goal]; at that level the question becomes [restated question]
Selected frame: [one candidate] — because [it unblocks / it changes the decision]
First move under the new frame: [concrete next action]
```

## Failure Modes
- Reframe as escape: stuck on hard execution, so the problem gets redefined into an easier one → require the new frame to explain why the old frame failed, not just to feel fresher
- Infinite ascent: every frame serves a higher goal and the elevation never lands → stop at the level where action is still possible; go no higher than the level that changes what you can do
- Frame shop without selection: five candidate frames generated, none chosen → pick one explicitly, state what it changes, and commit for a defined period
- Aphorism as authority: quotes justify the move but don't validate the new frame → a reframe earns its keep only if answering the new question changes the action, not the mood

## Evidence Strength
Practitioner consensus — reframing and problem elevation are staples of coaching, design thinking, and strategy practice, and cognitive research on problem representation supports the core claim that how a problem is posed constrains the solution space. There is no validated procedure for when to reframe or which frame to pick; the evidence is strongest for the diagnosis (being stuck often means the wrong frame) and weakest for the method (finding the better frame reliably).
