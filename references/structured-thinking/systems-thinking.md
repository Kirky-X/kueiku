# Systems Thinking · 系统思考

## 核心理念

系统不是部分的加总，而是相互连接的整体。系统思考关注反馈环路、延迟效应和非线性动态，帮助理解"为什么好的干预反而让情况更糟"。

> "今天的问题来自昨天的'解决方案'。" —— Peter Senge

## 适用场景

✅ **最适合**
- 反复出现的问题（修了又犯）
- 解决方案短期有效但长期恶化
- 多利益方互相影响的复杂局面
- 需要理解长期动态而非静态快照

⚠️ **慎用**
- 简单线性因果关系（用 5 Whys 即可）
- 需要快速行动（系统建模耗时）
- 团队无法理解反馈环路概念

## 执行步骤

### Step 1：界定系统边界

明确系统的范围、关键参与者（stakeholders）和时间跨度。

```
关键问题：
  系统的边界在哪里？（包含什么、排除什么）
  关键变量有哪些？（列出 5-10 个）
  时间跨度？（周/月/年级别）
```

### Step 2：识别反馈回路

找出三类核心回路：

```
回路类型：
  增强回路（Reinforcing）→ 正反馈，自我强化（如口碑传播、复利效应）
  平衡回路（Balancing）  → 负反馈，趋向稳定（如 thermostat、库存调节）
  延迟回路（Delay）      → 因果之间的时间差（如培训投入→能力提升→产出增加）

标注方式：
  用 + 表示同向变化（A↑ → B↑）
  用 - 表示反向变化（A↑ → B↓）
  用 || 表示延迟
```

### Step 3：绘制因果回路图（CLD）

将变量和回路可视化为因果回路图。

```
CLD 要素：
  变量 → 用名词表示（如"用户量""满意度""口碑"）
  因果链 → 箭头连接，标注 + 或 -
  回路标识 → R（增强）或 B（平衡）+ 编号
  延迟标注 → 在因果链上标注 ‖
```

### Step 4：识别存量与流量

区分"存量"（accumulation）和"流量"（rate of change）。

```
存量：某时刻可观测的量（如用户数、资金余额、知识储备）
流量：改变存量的速率（如新增用户、收入/支出、学习速度）

关键洞察：
  存量的变化速度 ≤ 流入速度（物理约束）
  人们通常关注流量而非存量，导致误判（如只关注收入不关注负债）
```

### Step 5：寻找杠杆点

找出系统中微小变化能产生重大影响的点。

```
杠杆点层级（按效力从低到高）：
  L1 参数调整 → 改变数字（如税率、价格）— 效果最小
  L2 反馈回路 → 改变信息流（如增加透明度）— 中等效果
  L3 系统规则 → 改变激励机制（如绩效考核方式）— 高效果
  L4 系统目标 → 改变系统目的（如从利润最大化转向用户价值）— 最高效果
```

## 常见陷阱

| 陷阱 | 避免方式 |
|------|---------|
| 过度建模——画出整个宇宙 | 聚焦 3-5 个核心变量，其余忽略 |
| 忽视延迟——期望立竿见影 | 显式标注延迟，设定合理预期 |
| 只看增强回路——忽视平衡力 | 每个增强回路配一个平衡回路 |
| 把 CLD 当装饰品——画完不用 | 用 CLD 预测干预效果，与实际对比 |
| 混淆相关与因果 | 用数据或领域知识验证每条因果链 |

## 与其他方法论的关系

- **搭配 Second-Order Thinking**：二阶思维关注决策连锁效应，系统思考提供结构化建模工具
- **搭配 Cynefin**：Cynefin 判断问题域，系统思考在"复杂"域中最有价值
- **搭配 First Principles**：无现成系统模型时，退回第一性原理重建
- **搭配 Value Chain Analysis**：价值链提供系统边界参考，系统思考揭示链上动态
- **搭配 Growth Loops**：增长飞轮是增强回路的商业化表达，系统思考提供更完整的回路分析
