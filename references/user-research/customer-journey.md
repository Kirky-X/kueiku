# Customer Journey Map

## Core Concept
Visualize the user's complete journey across all touchpoints, mapping actions, emotions, pain points, and opportunities at each stage. Enables service optimization and cross-department alignment.

## Applicable Scenarios
✅ **Best for**
- Service optimization
- Product experience design
- Cross-department alignment

⚠️ **When NOT to use**
- Pre-purchase touchpoint dynamics only — the **Consumer Decision Journey** models the consideration/advocacy loop more sharply; a journey map earns its cost when service stages (onboarding, support, renewal) enter scope
- No research in hand — mapping without interviews produces the org chart of wishes; start with interviews (**The Mom Test** format works)
- Every persona × scenario at once — comprehensive maps become wall art; fix the highest-impact persona/scenario pair first
- As a substitute for ownership — a map with no stage owners is a poster, not a tool

## Key Steps
1. Define the persona and scenario
2. Map journey stages: Awareness → Consideration → Purchase → Onboarding → Usage → Support → Renewal/Churn
3. For each stage, document: user actions, touchpoints, emotions (high/low), pain points
4. Identify "moments of truth" (critical decision points) and pain peaks
5. Prioritize improvement opportunities based on impact and feasibility
6. Share with cross-functional teams for alignment

## Output Template

```
Persona: [name]  Scenario: [specific goal]  Evidence: [# interviews / data sources]
Stage: [Awareness / Consideration / Purchase / Onboarding / Usage / Support / Renewal]
  Actions: [what the user does]
  Touchpoints: [where it happens]
  Emotion: [high/low + trigger]
  Pain points: [friction, ranked by severity]
Moments of truth: [critical decision points]
Top opportunities: [ranked by impact × feasibility, each with owner + metric]
```

## Failure Modes
- Aspirational journeys: stages drawn from how the process should work → source every action and emotion from interviews, logs or tickets; mark unverified cells as hypotheses
- Persona-stuffed maps: one generic "user" journey fits nobody → one persona and one scenario per map; parallel journeys get parallel maps
- Pain dumps without prioritization: 40 pain points, zero decisions → force-rank to the top 3 before the workshop ends
- Map-as-deliverable: a beautiful artifact nobody revisits → attach owners and metrics to the top opportunities and review at operating cadence

## Evidence Strength
Practitioner consensus — journey mapping is a standard service-design and CX practice with consistent reported value for cross-functional alignment; its output is only as good as the underlying research, and in practice most maps underweight evidence in favor of internal assumptions — treat unverified cells as hypotheses to test.

## Source
Service design methodology; widely used in UX and customer experience.
