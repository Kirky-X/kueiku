# Backtesting Framework · 量化回测框架

## 核心理念

用历史数据模拟策略执行过程，评估策略的收益、风险和稳健性。

回测是量化策略从"想法"到"实盘"的必经环节。一个好的回测框架必须解决三个核心问题：如何避免偏差（前视偏差、生存偏差、选择偏差）、如何真实模拟交易成本、如何检测过拟合。回测不是证明策略有效——而是尽可能发现它为什么无效。

> **核心理念**：回测的目标不是证明策略赚钱，而是证伪它。
> 任何策略都能在历史数据上"看起来赚钱"——关键是排除偏差后是否仍然赚钱。样本外测试、交叉验证和经济逻辑是三道防线。

---

## 适用场景

✅ **最适合**
- 量化策略上线前的验证
- 策略参数优化与稳健性检验
- 过拟合检测与模型选择
- 策略容量与流动性评估

⚠️ **慎用**
- 历史数据不代表的结构性变化（如政策变革）
- 极低频策略（样本量不足以统计推断）
- 依赖实时数据的策略（回测无法完全模拟延迟）
- 回测结果"太好"的策略（大概率过拟合）

## 执行步骤

### Step 1：数据准备与质量控制

回测的数据基础决定结果可信度：

```
数据类型：
  行情数据：
  - OHLCV（开高低收量）：日频/分钟频/Tick
  - 复权价格：前复权（回测用）vs 后复权（收益计算用）
  - 涨跌停标记、停牌标记

  基本面数据：
  - 财务报表数据（必须用 point-in-time，非当前快照）
  - 公告日期 vs 报告期末（关键！避免前视偏差）
  - 行业分类（历史行业，非当前行业）

  其他数据：
  - 指数成分股（历史成分，非当前成分——避免生存偏差）
  - 退市股数据（必须包含！）
  - 分红送股数据

  数据质量检查：
  - 缺失值：停牌日、新股上市首日
  - 异常值：除权除息未复权、数据源错误
  - 一致性：多数据源交叉验证
```

> 数据质量是回测的地基。垃圾数据 → 垃圾结论。Point-in-time 数据是避免前视偏差的最低要求。

### Step 2：策略信号定义

将策略逻辑转化为可计算的信号：

```
信号定义要素：
  1. 输入数据：使用哪些字段、什么频率
  2. 信号计算：具体的计算公式/模型
  3. 信号方向：做多/做空/中性
  4. 信号强度：连续值（如因子得分）或离散值（如买入/卖出）
  5. 调仓频率：日/周/月
  6. 约束条件：权重上限、行业限制、换手限制

  信号必须严格使用"当时可获得"的信息：
  - T 日信号 = f(T 日及之前的数据)
  - 不能使用 T+1 或更晚的数据
  - 财务数据按公告日，非报告期末
```

### Step 3：回测引擎执行

模拟策略的历史执行过程：

```
回测引擎核心逻辑：
  for each_date in trading_dates:
    1. 获取当日可用数据
    2. 计算信号（严格使用历史数据）
    3. 生成目标权重
    4. 计算与当前持仓的差异（换手）
    5. 模拟执行交易：
       - 以收盘价/ VWAP/ 开盘价成交
       - 扣除交易成本（佣金 + 冲击成本 + 滑点）
       - 检查流动性约束（参与率 ≤ X%）
    6. 更新持仓
    7. 记录当日盈亏

  关键参数：
  - 成交价格：收盘价 vs 次日开盘价 vs VWAP
  - 交易成本模型：
    固定成本：佣金（万 2-3）+ 印花税（千 1）
    冲击成本：√(成交额/日均成交额) × 波动率 × 系数
    滑点：信号日到执行日的价差
```

### Step 4：绩效评估

多维度评估策略表现：

```
收益指标：
  - 年化收益率
  - 超额收益（vs 基准）
  - 月度/年度胜率

风险指标：
  - 年化波动率
  - 最大回撤（金额、持续时间、恢复时间）
  - VaR / CVaR（95%/99%）
  - 下行波动率

风险调整收益：
  - 夏普比率 = (Rp - Rf) / σp，> 1 合格，> 2 优秀
  - 索提诺比率 = (Rp - Rf) / σ_downside
  - 卡尔马比率 = 年化收益 / 最大回撤，> 1 合格
  - 信息比率 = 超额收益 / 跟踪误差

  统计检验：
  - t 检验：超额收益是否显著（t > 2.0）
  - 自相关检验：收益是否存在自相关（策略信号重叠）
  - 偏度/峰度：收益分布是否正态
```

### Step 5：过拟合检测

这是回测最关键的环节：

```
过拟合检测方法：
  1. 样本外测试：
     - 训练集（60-70%）/ 测试集（30-40%）
     - 样本内夏普 >> 样本外夏普 → 过拟合

  2. 交叉验证：
     - 时间序列交叉验证（Purged K-Fold）
     - 避免数据泄露（训练集和测试集之间留缓冲期）

  3. 参数敏感性：
     - 对关键参数 ±20%，看绩效变化
     - 参数微调导致绩效剧变 → 过拟合
     - 参数"孤岛"（只有特定值有效）→ 过拟合

  4. 多重检验校正：
     - 测试了 N 个策略变体，最佳的可能只是运气
     - Bonferroni 校正 / FDR 控制
     - 经验法则：测试 20 个变体，最佳 t 值需 > 3.5

  5. Deflated Sharpe Ratio：
     - 校正尝试次数后的夏普比率
     - DSR = Φ(Φ⁻¹(SR) × √N_trials)

  红旗信号（大概率过拟合）：
  - 夏普 > 3（扣成本后）
  - 样本内夏普是样本外的 2 倍+
  - 只有特定参数组合有效
  - 策略逻辑缺乏经济解释
```

## 常见陷阱

| 陷阱 | 避免方式 |
|------|---------|
| 前视偏差 | 严格 point-in-time 数据，财务数据按公告日 |
| 生存偏差 | 包含退市股、使用历史指数成分 |
| 过拟合 | 样本外测试 + 参数敏感性 + Deflated Sharpe Ratio |
| 忽略交易成本 | 使用真实成本模型，不用"零成本"假设 |
| 回测结果"太好" | 夏普 > 3 大概率过拟合，需严格检验 |
| 用收盘价模拟执行 | 考虑 VWAP 或次日开盘价，收盘价不可执行 |
| 忽略流动性约束 | 检查参与率，小盘股策略需限制持仓规模 |
| 数据窥探偏差 | 记录所有测试过的策略变体，做多重检验校正 |

## 与其他方法论的关系

- **前置 Factor Investing / Momentum / Statistical Arbitrage**：所有策略都需要回测验证
- **前置 ML Stock Selection**：机器学习模型必须用回测框架做样本外验证
- **前置 Portfolio Optimization**：组合优化结果需回测确认样本外表现
- **前置 Risk Parity**：风险平价策略需回测验证不同市场环境下的稳健性
- **通用工具**：回测框架是量化投资模块的基础设施，所有策略方法论都依赖它
