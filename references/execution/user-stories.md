# User Stories · 用户故事

## 核心思想
用"As a [role], I want [feature], so that [benefit]"句式把需求从"系统要做什么"转换为"用户要完成什么"。配合 3 C's（Card/Conversation/Confirmation）与 INVEST 六准则，避免 backlog 沦为不可执行的 feature 清单。

## 适用场景
- 敏捷开发团队 backlog 管理
- 需求文档需从功能视角转用户视角
- story 写得太大或太小，无法规划 sprint

## 关键步骤
1. 写 story：As a [角色], I want [能力], so that [价值]
2. 应用 3 C's：
   - Card：故事卡片（一句话，可写在便签上）
   - Conversation：围绕卡片的对话（细节在讨论中浮现，不预先全部写死）
   - Confirmation：验收条件（"做到什么算完成"——可测试）
3. 用 INVEST 检验质量：
   - Independent（不依赖其他 story）
   - Negotiable（可协商细节）
   - Valuable（对用户有明确价值）
   - Estimable（可估算工作量）
   - Small（一个 sprint 内可完成）
   - Testable（有明确验收条件）
4. 不满足的 story 拆分或重写
5. sprint planning 时确认每条 story 的验收条件已定义

## 来源
Agile 标准实践；3 C's 来自 Ron Jeffries，INVEST 来自 Bill Wake
