# Outcome Roadmap · 结果导向路线图

## 核心思想
传统 feature roadmap 列"下季度做 X 功能"——这是 output，不是 outcome。Outcome Roadmap 强制把每条 roadmap 项转换为"Enable [segment] to [customer outcome] so that [business impact]"句式，让路线图可被业务结果验证而非按时交付。

## 适用场景
- 路线图沦为 feature 清单，无法回答"为什么做这个"
- 跨团队对路线图优先级争议不休
- 上线后没人能判断是否"成功"

## 关键步骤
1. 对每条 roadmap 项用模板转换：
   - Enable [目标 segment]
   - to [客户侧的具体 outcome]
   - so that [业务侧的具体 impact]
2. 检验：
   - 若填不出 customer outcome，说明这是个内部需求，不应进 roadmap
   - 若填不出 business impact，说明未与战略对齐
3. 按 outcome 价值排序，而非按 feature 工作量
4. 路线图条目保留 outcome + 候选方案（不要锁定单一方案）
5. 上线后回溯：customer outcome 是否达成？business impact 是否兑现？未达成则迭代或砍掉
