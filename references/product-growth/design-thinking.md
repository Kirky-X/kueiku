# Design Thinking

## Core Concept
Human-centered design loop: Empathize → Define → Ideate → Prototype → Test. A non-linear, iterative process for creative problem solving that keeps the user at the center.

## Applicable Scenarios
✅ **Best for**
- New product 0-to-1 design
- Service design
- Innovation workshops

⚠️ **When NOT to use**
- The problem is already well-defined and the question is technical execution — the loop's front end would re-litigate a settled problem
- Hard constraints dominate (regulatory, safety-critical) — user desirability can't veto engineering necessity; run compliance in parallel, not after
- Workshop-only adoption: one ideation offsite labeled "design thinking" with no user contact — empathy is the load-bearing stage; skip it and it's just brainstorming theater

## Key Steps
1. **Empathize**: conduct user interviews, observations, immerse in user context
2. **Define**: synthesize findings into a clear problem statement (point of view)
3. **Ideate**: generate many solutions (diverge), then select promising ones (converge)
4. **Prototype**: build quick, low-fidelity prototypes of top ideas
5. **Test**: put prototypes in front of users, learn, iterate

## Output Template

```
Empathy evidence: [n interviews / observations — key quotes and behaviors, not summaries]
POV (Define): [User] needs [need] because [insight] — one sentence, evidence-backed

Ideation: [n ideas generated] → converged shortlist [3], selection criteria: [desirability evidence / feasibility note]
Prototypes: [what each shows — deliberately low-fi: paper, clickthrough, service walkthrough]
Test rounds: [n users per round] — what users did/said → what changed as a result
Iteration log: [round → learning → change] — the loop's actual output

Exit: [validated concept + evidence, or killed cheaply — both are wins]
```

## Failure Modes
- Skipping to solutions: ideation starts before empathy evidence exists → no Define stage without named user evidence; count interviews before counting ideas
- Prototype inflation: pixel-perfect prototypes that took weeks — too precious to change or discard → fidelity matches the question being tested; if it hurts to throw away, it was overbuilt
- Test as validation ritual: showing prototypes hoping to hear "great" → tests are for learning what breaks; log behavior, not compliments

## Evidence Strength
Practitioner consensus — the process packages long-established design practices (user research, iterative prototyping); systematic reviews find benefits for user-centered outcomes but note weak comparative evidence and high variance in how teams apply it — the human-contact stages carry the value; the ceremony does not.
