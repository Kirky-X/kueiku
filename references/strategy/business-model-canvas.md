# Business Model Canvas

## Core Concept
9-block business model: Key Partners, Key Activities, Key Resources, Value Propositions, Customer Relationships, Channels, Customer Segments, Cost Structure, Revenue Streams. One-page complete business model visualization.

## Applicable Scenarios
✅ **Best for**
- Startup/transformation business model design
- Competitive business model analysis
- Business model pivot

⚠️ **When NOT to use**
- Hypothesis-stage startup without customer evidence — Lean Canvas's problem/assumption framing fits better
- Product-feature decisions — the canvas is business-model altitude; features live elsewhere
- Multi-sided markets treated as one side — draw one canvas per side or the economics average away

## Key Steps
1. Fill each of the 9 blocks (recommended order: Value Prop → Segments → Channels → Relationships → Revenue → Key Resources → Key Activities → Key Partners → Cost Structure)
2. Validate internal consistency between blocks
3. Identify risks and assumptions per block
4. Compare with competitor business models

## Output Template

```
Key Partners        | Key Activities            | Value Propositions      | Customer Relationships | Customer Segments
[who we don't own]  | [what we must do daily]   | [why customers pick us] | [how we acquire/keep]  | [who pays, ranked]
                    | Key Resources             |                         | Channels               |
                    | [assets we can't lose]    |                         | [how value reaches]    |
Cost Structure (top items + dominant driver): [...]
Revenue Streams (model + price + who): [...]

Consistency checks: Segments ↔ Channels [ok/conflict], Value Prop ↔ Revenue [ok/conflict], Resources ↔ Cost [ok/conflict]
Riskiest assumption: [block + assumption] → test: [experiment by date]
```

## Failure Modes
- Everything-for-everyone blocks: 5 segments, 6 value props — the canvas averages into mush → rank and cap: top segment, one core value prop
- Revenue stream fantasy: prices copied from wishes, not willingness-to-pay → mark each revenue number as tested/assumed
- Consistency skipped: each block plausible alone, combination incoherent (premium value prop, bargain channels) → run the three checks out loud with the team

## Evidence Strength
Practitioner consensus — the dominant shared vocabulary for business-model work; it structures description and comparison but validates nothing itself, and its 9-block split is a convention rather than an empirically derived model.
