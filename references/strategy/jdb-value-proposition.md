# JDB Value Proposition

## Core Concept
6-block JTBD template: Who / Why / What before / How / What after / Alternatives. Crystallize a challengeable value proposition.

## Applicable Scenarios
✅ **Best for**
- Distilling a challengeable value proposition before writing PRD or website

⚠️ **When NOT to use**
- No validated job statement yet (uninterviewed users) — the template will only organize guesses; run The Mom Test first
- Positioning against named competitors is the real task — use Positioning Strategy
- Internal tools with a single captive user — "alternatives" is trivially "do nothing", the template degenerates

## Key Steps
1. Who: who is the customer?
2. Why: why do they care?
3. What before: what's their current situation?
4. How: how does your product help?
5. What after: what does their life look like after?
6. Alternatives: what would they do without you?

## Output Template

```
Who:         [specific user, not a demographic]
Why:         [the job/anxiety that makes this urgent now]
What before: [current workflow and its cost — minutes/money/errors]
How:         [what we do differently, in one sentence]
What after:  [observable after-state, ideally measurable]
Alternatives: [spreadsheet / agency / do nothing / competitor] — why we beat each: [one line]

One-sentence value proposition: [Who] uses [product] to go from [before] to [after] instead of [alternative], because [how].
Challenge: would [Who] repeat this sentence back to a colleague? If not, it isn't crisp yet.
```

## Failure Modes
- Persona fog: "Who" is a segment ("marketers") instead of a person with a job → write it so you could name a real customer who matches
- After-state unmeasurable: "better collaboration" — measure nothing → force a number or observable event into "What after"
- Alternatives dismissed: the do-nothing option wins more often than teams admit → argue seriously for each alternative before dismissing it

## Evidence Strength
Practitioner consensus — a structuring device descended from Jobs-to-be-Done practice; it improves proposition clarity (testable by whether users repeat it back) but makes no empirical claim of its own.
